title O-RAN E2SM-RC DRB QoS Configuration (Style 1 / Action 1) - Sequence Diagram

participant xApp
participant "near-RT RIC\n(E2Term)" as RIC
participant "gNB CU-CP\n(E2 Agent, NGAP, E1AP-c, F1AP-c, RRC)" as CUCP
participant "gNB CU-UP\n(PDCP-U, SDAP)" as CUUP
participant "gNB DU\n(F1AP-DU, MAC Scheduler)" as DU
participant UE

alt Standard 3GPP-driven QoS change (equivalent standard trigger)
  note over CUCP: AMF/PCF -> NGAP PduSessionResourceModifyRequest\n(3GPP TS 38.413 S9.2.1.14) - same downstream procedure as below
else RIC-driven QoS change (E2SM-RC control path)
  xApp->RIC: E2AP RICcontrolRequest\n(RANfunctionID=E2SM-RC, ricStyleType=1,\nricControlActionID=1, ricControlHeader=gNB-UEID)
  RIC->CUCP: route to matching E2 Node\n(the CU-CP's E2 Agent - Radio Bearer\nControl is a CU-CP-side procedure)
  CUCP->CUCP: E2SM-RC control handler parses RAN\nparameters (DRB ID, 5QI, GBR-QoS-Info\n{MFBR DL, MFBR UL}) and resolves\nthe target UE context
end

note over CUCP: Both trigger paths converge on the same\nCU-CP QoS-modification procedure used for a\nstandard, core-network-driven PDU Session Resource Modify

CUCP->CUCP: derive the updated per-DRB QoS context\n(all unmodified QoS fields carried forward unchanged)

CUCP->CUUP: E1AP BearerContextModificationRequest\n(3GPP TS 38.463) - DRB-to-Modify list:\nupdated GBR-QoS-Information
CUUP-->CUCP: E1AP BearerContextModificationResponse\n(confirms the modified DRB)

CUCP->DU: F1AP UEContextModificationRequest\n(3GPP TS 38.473) - DRBs-To-Be-Modified-List:\nqoSInformation.dRB-QoS.gBR-QoSFlowInformation

DU->DU: update local per-DRB QoS configuration

DU->DU: MAC scheduler applies the new MFBR as a\nper-DRB (DL) / per-LCG (UL) rate-limiting\ncap (e.g. a token-bucket mechanism)
note right of DU: **Enforcement point.**\nNo further signaling needed\nfrom here on.

DU-->CUCP: F1AP UEContextModificationResponse

alt PDCP or SDAP configuration actually changed
  CUCP->DU: RRC RRCReconfiguration (3GPP TS 38.331)\nvia F1AP DLRRCMessageTransfer (SRB1)
  DU->UE: RRC RRCReconfiguration
  UE-->DU: RRCReconfigurationComplete
  DU-->CUCP: F1AP ULRRCMessageTransfer
else MFBR-only change (no RRC-visible delta)
  note over CUCP,UE: DRB omitted entirely from\nradioBearerConfig.drb-ToAddModList -\nno RRC message sent (TS 38.331\n"signal only deltas" principle)
end

CUCP-->RIC: E2AP RICcontrolAcknowledge\n(accepted for processing, not completion)
RIC-->xApp: control acknowledged

loop every subsequent slot
  DU->DU: PDSCH/PUSCH grant sizing clamped\nagainst the configured per-DRB (DL) /\nper-LCG (UL) rate limit
end

note over DU,UE: DL enforcement is exact (the gNB builds the PDSCH grant itself).\nUL is exact only if the GBR DRB has a dedicated LCG -\nTS 38.321 Logical Channel Prioritization runs\nin the UE, not the gNB.
